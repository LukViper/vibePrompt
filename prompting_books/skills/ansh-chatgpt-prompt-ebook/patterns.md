# Patterns — Ansh Mehra ChatGPT eBook (Think School)

## Prompt Anatomy (Role → Task → Goal → Constraints/Expectations)
**When to use**: Any non-trivial ChatGPT ask (learning, marketing, content, UX).
**How**: (1) ASSIGN A ROLE with specialty. (2) DEFINE THE TASK as a deliverable. (3) DEFINE THE GOAL / purpose. (4) SET CONSTRAINTS and EXPECTATIONS (format, length, wait rules, resource quality).
**Trade-offs**: Longer prompts take effort; vague short prompts waste more iterations.

## Framing (Specialist Persona)
**When to use**: Domain judgment matters (career, nutrition, copy, research).
**How**: `Act as a [senior specialty] who focuses on [narrow niche]` before the ask.
**Trade-offs**: Over-narrow personas can miss cross-domain insight; under-narrow personas stay generic.

## Best-Friend Context Dump
**When to use**: Plans that depend on your background, timeline, geography, or skill level.
**How**: Include current state, target outcome, constraints (budget, free resources), and deadline.
**Trade-offs**: Irrelevant detail adds noise; omit only what cannot affect the plan.

## Constraint Decomposition (Multi-Step Build)
**When to use**: Book-scale or system-scale outputs.
**How**: Sequence prompts (topics → outline → subheads → expand → simplify → human edit). Feed prior outputs forward.
**Trade-offs**: More turns; far higher structure and originality than one mega-prompt.

## Weekly Mentor Routine
**When to use**: Skill growth needs cadence, not tips.
**How**: Senior `[subject]` mentor + focus topic + uncommon advice + underrated resources.
**Trade-offs**: Generic without the uncommon/underrated constraint.

## Legendary Personality Mentorship
**When to use**: You want a specific thinker’s decision style on a doubt.
**How**: Name personality; require mental models + tone; end with one actionable step; optionally multiple personalities.
**Trade-offs**: Caricature risk if the person is poorly specified; always demand the action closer.

## Rule-Explicit Trivia Game
**When to use**: Drill theory with engagement.
**How**: MCQ rounds; points; win threshold; wait for answers; stop/reset phrases; single correct option.
**Trade-offs**: Brittle if rules are implied; spell every control out.

## Social Growth Coach + Calendar
**When to use**: Need audience, topics, strategy, and a posting schedule together.
**How**: Niche coach + current metrics + target + timeline + 30-day calendar; keep goals realistic.
**Trade-offs**: Fantasy follower targets produce unusable or risky tactics.

## Feature-Led Ad Copy
**When to use**: Ads must convert a defined segment on a channel.
**How**: Specialist copywriter + brand/product + channel + audience + conversion objective + feature list → benefits.
**Trade-offs**: Feature dumps without audience/objective read like brochures.

## AIDA Cold Email
**When to use**: Personalized outreach introducing a product to a named person.
**How**: Cold-email specialist + recipient context + features + personal benefits + AIDA + concise reply-seeking tone.
**Trade-offs**: Rigid AIDA can feel formulaic; personalization must still sound human.

## Sponsored Dual-Format Content
**When to use**: Tutorial content that also promotes a product.
**How**: Niche creator role + educational visual piece + companion blog + sponsor demonstration criteria + audience.
**Trade-offs**: Heavy sponsor focus can kill trust if education is thin.

## Creator Content Calendar (Curated + Original)
**When to use**: Sustained posting for a niche audience.
**How**: Marketing-manager role + psychographics + visual bar + seasonal/trend hooks + hashtags + curated/original mix.
**Trade-offs**: Over-scheduling without capacity causes abandonment.

## UX Research Mentor Brief
**When to use**: Learn or standardize user research operations.
**How**: Senior UX mentor + end-to-end steps + examples + method-by-question logic + free/low-cost tools.
**Trade-offs**: Generic “do research” answers if examples/tools omitted.

## Design-System State Table
**When to use**: Specifying components before engineering handoff.
**How**: Design-system manager + component + platform + table of interactive states and edge cases.
**Trade-offs**: Tables without edge cases still ship bugs.

## Turn-Based Mock Interview
**When to use**: Interview rehearsal under realistic pacing.
**How**: Recruiter persona; N questions; only interviewer speech; one Q at a time; wait; later feedback + resources + tips.
**Trade-offs**: Without wait rules, the model dumps the script and practice collapses.

## Build-on-Top Editing
**When to use**: After any useful completion.
**How**: Treat output as clay; rewrite in your voice; verify facts; add constraints the model missed.
**Trade-offs**: Extra time; required for distinctive, trustworthy work.

## Active Prompt Study (No Blind Paste)
**When to use**: Learning from ebooks, PromptVine, PromptBase, etc.
**How**: Read why it works → type your variant → save anatomy notes → iterate.
**Trade-offs**: Slower than paste; much higher retention and transfer.
