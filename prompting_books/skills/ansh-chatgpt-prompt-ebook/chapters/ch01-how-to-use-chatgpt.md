# Chapter 1: How to use ChatGPT?

## Core Idea
ChatGPT is a chat interface—no coding required—but weak prompts produce weak results; **Prompt Engineering** (writing great prompts) is how you 10× output quality.

## Frameworks Introduced
- **Prompt Engineering**: The skill of crafting messages so the model returns useful, high-quality results.
  - When to use: Whenever you ask an AI tool for work, learning, or creative help—not only for “advanced” tasks.
  - How: Treat every message as a designed request; learn frameworks, techniques, and resources later in the ebook, then adapt as tools change.
- **Principle-first adaptation**: AI tools change fast; principles transfer, UI and model versions do not.
  - When to use: When a button, model name, or feature from a guide looks outdated.
  - How: Extract the underlying rule (role, context, constraints, iteration) and re-apply it in the current product.
- **Active eBook practice loop**: Learn by selecting, documenting, typing, and building—not by passive reading.
  - When to use: Studying any prompt guide or template library.
  - How: (1) Pick sections that match your goals—no forced linear read. (2) Document learnings (e.g. Notion). (3) Type prompts yourself instead of copy-paste. (4) Treat AI output as a starting point you improve.

## Key Concepts
- **Prompt**: Every message you type into an AI tool.
- **Prompt Engineering**: Fancy name for writing prompts that reliably get strong results.
- **Weak-prompt trap**: Blaming the tool when the request was underspecified.
- **Adaptation responsibility**: You must keep updating practice as the AI landscape shifts.
- **Hands-on practice**: Typing and iterating prompts trains memory better than pasting templates.

## Mental Models
- Use **Prompt Engineering** when results feel generic or wrong—fix the request before switching tools.
- Think of **ChatGPT as a chat partner**, not a search box that magically knows your full context.
- Prefer **principles over recipes** when product UIs or model tiers change.
- Use **document → type → build-on** when studying prompt examples so you retain structure, not surface wording.

## Anti-patterns
- **Copy-pasting prompts blindly**: Skips comprehension; weakens memory and transfer to new tasks.
- **Reading cover-to-cover with no application**: Volume without practice does not improve prompting skill.
- **Treating ebook outputs as final answers**: AI and guides are starting points; outstanding results require your judgment on top.
- **Assuming the landscape is static**: Clinging to outdated steps instead of re-applying principles.

## Worked Example
**Situation**: You find a “perfect” weekly-skill prompt online and want better UX practice.

**Passive path (avoid)**: Paste → skim answer → forget structure next week.

**Active path (author method)**:
1. Read why the prompt assigns a *senior mentor*, names a *focus topic*, and asks for *uncommon + underrated* resources.
2. Type a rewritten version for *your* skill (e.g. “senior product-marketing mentor… especially for B2B LinkedIn”).
3. Save the anatomy notes in Notion: Role / Task / Constraints.
4. Edit the model’s routine with your real calendar constraints.

**Why it works**: Typing forces you to notice each design choice; documentation creates a reusable personal playbook.

## Key Takeaways
1. Every AI message is a prompt—design it deliberately.
2. Prompt Engineering is the multiplier between “chat” and useful work output.
3. Skip linear reading; prioritize sections that match your goals.
4. Type prompts yourself; don’t paste-and-pray.
5. Keep practicing and updating—tools move faster than any single ebook.
