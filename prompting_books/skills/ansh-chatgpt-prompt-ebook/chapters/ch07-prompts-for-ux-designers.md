# Chapter 7: Prompts for UX Designers

## Core Idea
UX prompts shine when a senior design role delivers structured methods, examples, tool lists, table-formatted checklists, or **turn-based mock interviews** that wait for answers—never dump the whole script at once.

## Frameworks Introduced
- **Senior UX Mentor — User Research Study**: Explain how to run research end-to-end with recruitment, analysis, method selection, examples, and low-cost tools.
  - When to use: Building or standardizing research practice; teaching juniors; resource-constrained startups.
  - How: Act as senior UX Design Mentor; require steps + real examples + method-choice logic by research question + free/low-cost tool list.
- **UI Design System Manager — Component State Checklist**: Table of interactive states and edge cases for a component (e.g. iOS button).
  - When to use: Hardening a design system before handoff.
  - How: Act as Sr. UI Design System Manager; name component + platform; demand table format; include all interactive states and edge cases.
- **Turn-Based Mock Interview**: HR recruiter persona runs a live interview one question at a time, then feedback + resources + tips.
  - When to use: Interview prep for UX roles (book example: Google UX designer hire).
  - How: Prepare ~10 questions; only reply as interviewer; no full conversation dump; wait for answers; start with “Hello”; after session: feedback, free prep resources, key tips.

## Key Concepts
- **Method–question fit**: Choosing research methods from the research question, not habit.
- **Interactive states & edge cases**: Design-system completeness beyond the happy path.
- **Table-formatted output**: Forces checklist completeness and scanability.
- **Conversational control**: Explicit “wait for my answer” prevents script dumps.
- **Post-interview coaching**: Feedback + resources extend practice beyond the mock.

## Mental Models
- Use a **research mentor prompt** when you need process literacy, not a single survey question.
- Use a **state checklist table** when components break in edge cases in production.
- Use a **turn-based interviewer** when you need pressure practice, not a Q list to memorize silently.
- Prefer **examples + tools** constraints when advice would otherwise stay theoretical.
- Think of mock interviews as **games systems** (like Ch 3 trivia): rules about turn-taking are the product.

## Anti-patterns
- **“Explain user research” without recruitment/analysis/tools**: Incomplete operational picture.
- **Component specs without edge cases**: Misses disabled, loading, error, focus, etc.
- **“Ask me interview questions” without wait rules**: Model pastes all ten at once.
- **Letting the model break character mid-mock**: Dilutes practice realism.

## Worked Example
**Mock interview control block** (reconstructed essentials):
1. Role: HR Recruiter at Google hiring a UX designer.
2. Prep: ten likely questions; later feedback + free resources + tips.
3. Hard constraints: only interviewer replies; one question at a time; wait; no explanations during Qs; greet with “Hello.”

**Opening completion shape**: `Hello…` → readiness check → first question only.

**Design-system button checklist ask**: Sr. UI Design System Manager; iOS button; table of states + edge cases—expect default/hover/pressed/disabled/loading/focus/error-type rows (exact labels vary by completion).

**Research mentor ask**: Define questions/goals → recruit → choose method → analyze → tools—with concrete illustrations.

## Key Takeaways
1. UX mentor prompts should demand process, examples, method logic, and tools.
2. Design-system prompts should force tables covering interactive and edge states.
3. Mock interviews need strict turn-taking rules to feel real.
4. Post-session feedback and resource lists turn practice into a study plan.
5. Same Prompt Anatomy as marketing/content—domain swaps, structure stays.
