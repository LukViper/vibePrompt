# Chapter 2: Installing ChatGPT in your Computer

## Core Idea
Getting started is account creation and verification on ChatGPT’s web app—then you chat at the bottom of the screen; beginners can practice fully on the free tier before paying for a higher model.

## Frameworks Introduced
- **Sign-up → Verify → Chat**: Minimal setup path for non-technical users.
  - When to use: First-time access or when onboarding someone with no coding background.
  - How: Visit the ChatGPT site → Sign Up → create account → verify email + phone OTP → land in the free chat UI → type in the bottom input.
- **Tiered practice strategy**: Free model for skill-building; paid model as an upgrade after basics feel solid.
  - When to use: Deciding whether to subscribe immediately.
  - How: Test prompting craft on the free version first; upgrade when you need higher-quality completions for real work.
- **No-code access rule**: If you can chat, you can use the tool—programming is not a prerequisite.
  - When to use: Reducing intimidation for beginners.
  - How: Frame ChatGPT as a conversation interface, not a developer environment.

## Key Concepts
- **ChatGPT web app**: Browser-based access (book cites chat.openai.com as of its writing).
- **Account verification**: Email confirmation plus phone OTP before use.
- **Free vs paid tiers**: Book’s snapshot—GPT-3.5 free; GPT-4 paid (~$20/mo); treat numbers as historical, principles as durable.
- **Chat input**: Bottom-of-screen field where prompts are entered.
- **Installation (practical sense)**: Creating access on your computer via the website, not installing local model weights.

## Mental Models
- Use the **free tier first** when you are still learning prompt structure.
- Think of **setup as minutes, mastery as practice**—account creation is not the skill.
- Prefer **browser chat** when the goal is prompting literacy, not local deployment.
- Upgrade models when **output quality for production work** is the bottleneck, not when you are still writing vague prompts.

## Anti-patterns
- **Skipping verification and blaming “broken” access**: Incomplete signup blocks use.
- **Paying immediately to “learn better”**: A paid model cannot fix underspecified prompts.
- **Assuming coding knowledge is required**: Creates unnecessary barrier for beginners.
- **Treating UI screenshots as eternal truth**: Layout and pricing change; the chat-at-bottom pattern remains the idea.

## Worked Example
**Goal**: A student wants ChatGPT available tonight for upskilling prompts (Ch 3).

**Steps (reconstructed from author flow)**:
1. Open the ChatGPT website → **Sign Up**.
2. Enter details → verify email → complete phone OTP.
3. Confirm free-tier access loads.
4. Locate the bottom chat box; send a tiny test: “Reply with one sentence confirming you can help me practice UX skills.”
5. Only after prompts feel structured (role + task + constraints) consider a paid tier for harder tasks.

**Failure mode**: Buying Plus on day one, then typing one-line questions—money spent, skill unchanged.

## Key Takeaways
1. Access = signup + verification + chat; no code required.
2. Practice prompting on free access before optimizing for model tier.
3. The chat input is the whole interface for beginners.
4. Pricing and model labels age quickly—re-check current product pages.
5. Next chapters show *what* to ask once access exists.
