# Chapter 8: Tooling, Limitations, and Outlook

## Core Idea
**Tooling** scales canvas practice (apps, libraries, arenas, custom GPTs, APIs); treat the Prompt Canvas as a **living, text-to-text-first** framework with known limits (agents, multimodality, risk analysis out of scope).

## Frameworks Introduced
- **Tooling (canvas category)**: Practical support layer beside Recommended Techniques.
  - When to use: Team rollout, reuse, comparison, or product integration.
  - How: Pick tools by job — draft faster, optimize, reuse, compare models, or embed via API.
- **LLM Apps**: Voice-first capture (e.g. ChatGPT app) for faster prompt drafting on the go.
- **Prompting Platforms**: Interactive design/test/optimize (e.g. PromptPerfect) with performance feedback.
- **Prompt Libraries**: Reusable templates (PromptHero free sharing; PromptBase marketplace) grounded in pattern thinking (White).
- **Browser Extensions**: In-page prompt experiments (e.g. Text Blaze, Prompt Perfect).
- **LLM Arenas**: Side-by-side model comparison (e.g. Chatbot Arena) to stay current on model strength.
- **Custom GPTs / company-wide LLMs**: Specialized assistants (ScholarGPT, Prompt Perfect) or org-primed models with docs/APIs/sandboxing.
- **API integration**: Embed LLMs into application systems for automated prompting at scale.

## Key Concepts
- **Living document**: Canvas should absorb or retire techniques as models change (e.g. built-in CoT in advanced reasoning models).
- **Text-to-text focus**: Primary modality of this work; image/audio/video prompting not highlighted.
- **Agent techniques excluded**: Multi-agent setups set aside in synthesis though potentially high-impact.
- **Domain customization**: Add cells (e.g. healthcare ethics, marketing creative constraints) without abandoning the core four categories.
- **Validation gap**: Utility needs further quantitative/qualitative evaluation; paper positions canvas as a starting point for discussion.

## Mental Models
- Use **libraries/patterns** when starting from a blank canvas; use **arenas** when choosing models; use **custom GPTs/APIs** when institutionalizing Context/References.
- Prefer **sandbox enterprise modes** when confidential context must not train public models.
- Think **modular canvas**: swap techniques in/out as models internalize former prompt tricks.

## Anti-patterns
- **Tool shopping before filling primary cells**: Platforms cannot fix a missing Task or Audience.
- **Treating the canvas as frozen dogma**: Ignoring model advances that change which techniques still matter.
- **Assuming coverage of risks**: Bias, privacy, copyright, and energy impact are acknowledged as out of scope — handle separately.

## Worked Example
**Company rollout**:
1. Train staff on the four primary categories + Art Horizon-style worked fill.
2. Store winning prompts in a library with placeholders for product names.
3. Provide a custom GPT primed with brand tone guide (Tonality + References).
4. Compare two model vendors in an arena on the same canvas-filled prompt.
5. API-wrap the winning template into the CMS “generate draft” button.
6. Review quarterly: drop techniques the new model already does natively.

## Key Takeaways
1. Tooling accelerates design, reuse, comparison, and integration.
2. Custom GPTs/APIs operationalize Context, References, and Tonality at org scale.
3. Canvas is adaptable and meant to evolve with the field.
4. Limits: text-to-text emphasis, individual prompts (not agents), limited risk analysis, evaluation still pending.
5. Outlook: dialogue tool for which techniques stay relevant as models absorb CoT-like behavior.
