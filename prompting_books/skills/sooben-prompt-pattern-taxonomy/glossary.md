# Glossary

**Alias** — Alternative source name for the same canonical pattern; recorded rather than creating a duplicate entry. (Ch 2, Ch 9)
**AlternativeApproaches** — Lists multiple viable approaches to the same task. (Meta-Directives; Ch 8)
**Answer space** — Admissible set of values/labels an answer may take; folded under SchemaSpecs. (Ch 6)
**Boundary overlap** — Patterns with similar surface form but different primary intention (e.g., Persona vs ContextManager). (Ch 9)
**Candidate pattern** — Named prompting concept extracted from sources before scope filtering. (Ch 2)
**Canonical structure** — Generic variables + template describing how to instantiate a pattern. (Ch 1, patterns.md)
**Chain-of-Thought (subcategory)** — Reasoning patterns that elicit intermediate reasoning before the final answer. (Ch 5)
**ChainOfThought** — Elicits explicit intermediate reasoning before the final answer. (Reasoning; Ch 5)
**CognitiveVerifier** — Generates subquestions whose answers support final verification. (Meta-Directives; Ch 8)
**Combination** — Reported technique that fuses broader patterns; often stored as a variant. (Ch 9)
**ComplexCoT** — Generates multiple detailed reasoning paths before answer selection. (Reasoning; Ch 5)
**Component annotation** — Multi-label metadata of where a pattern can appear in a prompt. (Ch 3)
**Composition** — Instantiating several patterns in one prompt, usually on different components. (Ch 9)
**Constraints (component)** — Restrictions/requirements the response should satisfy. (Ch 3)
**Context (component)** — Background or input content needed for the task. (Ch 3)
**Context Control** — Strategy family for role/perspective or contextual grounding. (Ch 7)
**Context Grounding** — Subcategory anchoring responses in provided context or lenses. (Ch 7)
**ContextManager** — Controls the contextual scope, included or excluded information, and disciplinary lenses used during response generation. (Context Control; Ch 7)
**Decomposition** — Reasoning subcategory that breaks tasks into simpler→harder subproblems (LeastToMost). (Ch 5)
**Directive (component)** — Main task, instruction, or question. (Ch 3)
**Enhancement (subcategory)** — Meta-Directives that improve/enrich a prompt or answer. (Ch 8)
**Examples (component)** — Sample inputs/outputs demonstrating expected behavior; only FewShot in this catalog. (Ch 4)
**FactCheckList** — Lists factual claims needed to verify the output. (Output Control; Ch 6)
**Few-Shot (subcategory)** — Guide the model through one or more examples. (Ch 4)
**FewShot** — Supplies worked input-output examples before the target task. (In-Context Learning; Ch 4)
**FlippedInteraction** — Makes the model ask questions to reach a goal. (Meta-Directives; Ch 8)
**GamePlay** — Frames the task as a rule-governed game. (Meta-Directives; Ch 8)
**In-Context Learning** — Strategy family controlling omission or use of examples. (Ch 4)
**InfiniteGeneration** — Continues generating repeated outputs until a stop condition. (Meta-Directives; Ch 8)
**InstructionSelection** — Selects among candidate instructions before executing the task. (Meta-Directives; Ch 8)
**Interaction (subcategory)** — Meta-Directives shaping how the model interacts with the user/request. (Ch 8)
**LeastToMost** — Decomposes tasks from simpler subproblems to harder ones. (Reasoning; Ch 5)
**Meta-Directives** — Strategy family acting on the prompt/query/interaction itself. (Ch 8)
**MetaLanguageCreation** — Defines custom shorthand semantics for subsequent prompt use. (Context Control; Ch 7)
**Output Control** — Strategy family constraining form, schema, procedure, or verification. (Ch 6)
**Output Format/Style (component)** — Expected structure, format, or style of the response. (Ch 3)
**Output Formatting (subcategory)** — Patterns specifying form/layout/presentation. (Ch 6)
**OutputAutomater** — Requires a structured, machine-readable output format such as JSON, XML, or CSV. (Output Control; Ch 6)
**Persona** — Canonical Context Control pattern assigning role/identity/expertise/perspective. (Ch 7)
**Persona** — Adopts a role or persona to shape responses. (Context Control; Ch 7)
**PlanAndSolve** — Plans subproblems before executing stepwise solution steps. (Reasoning; Ch 5)
**Planning (subcategory)** — Separate plan construction from execution (PlanAndSolve). (Ch 5)
**Procedural (subcategory)** — Output Control patterns specifying an in-prompt procedure (Recipe). (Ch 6)
**Procedural Steps (component)** — Steps/procedures inside a single prompt (renamed from Workflow). (Ch 1, Ch 3)
**Profile/Role (component)** — Who/what the model should act as; only Persona annotated here. (Ch 7)
**Prompt / prompt instance** — String submitted to an LLM without modification in a given interaction. (Ch 1)
**Prompt component** — Functionally identifiable part of a prompt (Mao et al.’s seven types). (Ch 1)
**Prompt pattern** — Recurring reusable textual structure in canonical form, instantiable in a prompt for a specific intention. (Ch 1)
**Prompt template** — Reusable prompt structure with placeholders before instantiation. (Ch 1)
**Prompt workflow** — Interaction-level multi-step procedure; out of taxonomy scope. (Ch 1)
**Prompting strategy** — Category grouping patterns by primary prompting intention. (Ch 1, Ch 3)
**QuestionRefinement** — Improves or reformulates the user query for clarity. (Meta-Directives; Ch 8)
**RAR** — Rephrases and expands the question before answering it. (Meta-Directives; Ch 8)
**RE2** — Re-reads the question before producing an answer. (Meta-Directives; Ch 8)
**Reasoning** — Strategy family for intermediate reasoning structures. (Ch 5)
**Recipe** — Specifies a reusable ordered procedure for completing tasks. (Output Control; Ch 6)
**Refinement (subcategory)** — Meta-Directives that rewrite/clarify/transform the query. (Ch 8)
**Reflection** — Critiques an initial answer and improves the response. (Output Control; Ch 6)
**RefusalBreaker** — Reframes refused requests into answerable alternative phrasings. (Meta-Directives; Ch 8)
**ReverseCoT** — Works backward from the desired output to infer the inputs or steps that produce it. (Reasoning; Ch 5)
**Role & Perspective** — Context Control subcategory for assigning role/identity/expertise. (Ch 7)
**Schema Specification** — Output Control subcategory for explicit schemas/fields/value spaces. (Ch 6)
**SchemaSpecs** — Constrains output to a specified schema or field structure. (Output Control; Ch 6)
**SelfCalibration** — Estimates answer confidence and revises or abstains when uncertain. (Output Control; Ch 6)
**SelfVerification** — Checks and revises its answer before finalizing output. (Output Control; Ch 6)
**Semantic consolidation** — Merging differently named concepts that share intention. (Ch 2)
**Single-turn** — One prompt instance; taxonomy’s interaction bound. (Ch 1)
**Specialization** — Narrower pattern form preserving parent intention. (Ch 9)
**StructuredCoT** — Organizes reasoning with explicit program-like control structures. (Reasoning; Ch 5)
**Template** — Fills a reusable template while preserving its structure. (Output Control; Ch 6)
**Tension** — Pattern interaction that weakens or constrains another. (Ch 9)
**Variant** — Alternative form or specialization recorded under a canonical pattern. (Ch 2, Ch 9)
**Verification (subcategory)** — Output Control patterns that check/validate/assess answers. (Ch 6)
**VisualizationGenerator** — Produces visual or tabular representations of information. (Output Control; Ch 6)
**Zero-Shot (subcategory)** — Guide the model without task-specific examples. (Ch 4)
**ZeroShot** — Instructs the task directly without worked examples. (In-Context Learning; Ch 4)
